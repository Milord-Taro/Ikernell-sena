# 06.7 Política de Seed y Datos de Demostración

## Objetivo

Definir la estrategia para poblar la base de datos de IKernell V2 de forma organizada, reutilizable y alineada con las buenas prácticas de ingeniería de software.

---

# Principios

Se establece una separación clara entre:

- Datos mínimos necesarios para que el sistema funcione.
- Datos utilizados únicamente para demostraciones, pruebas y desarrollo.

Esta separación facilita el mantenimiento, evita inconsistencias y permite desplegar el sistema en distintos entornos.

---

# Seed del Sistema

El **Seed** corresponde a los datos mínimos que toda instalación del sistema debe contener.

Estos registros representan catálogos base del negocio y pueden ser ampliados posteriormente mediante los respectivos módulos CRUD.

Los archivos Seed se ejecutarán una única vez al crear la base de datos.

# Datos de Demostración

Los datos de demostración **no forman parte del Seed**.

Su objetivo es facilitar:

- Desarrollo.
- Pruebas funcionales.
- Sustentación del proyecto.
- Demostraciones.

Se almacenarán en un archivo independiente.

```
20_demo_data.sql
```

---

## Datos sugeridos

El archivo podrá incluir:

- Usuarios.
- Proyectos.
- Integrantes del proyecto.
- Etapas.
- Actividades.
- Registro de errores.
- Interrupciones.
- Mensajes de contacto.
- Notificaciones.
- Registros de trazabilidad.

Estos datos podrán eliminarse o modificarse sin afectar el funcionamiento del sistema.

---

# Convención de Códigos

Todas las entidades utilizarán códigos funcionales únicos con prefijos definidos por el dominio.

| Entidad | Prefijo | Ejemplo |
|---------|----------|----------|
| Rol | ROL | ROL-001 |
| Profesión | PRO | PRO-001 |
| Especialidad | ESP | ESP-001 |
| Usuario | USR | USR-001 |
| Proyecto | PRY | PRY-001 |
| Etapa | ETA | ETA-001 |
| Actividad | ACT | ACT-001 |
| Tipo de Error | TER | TER-001 |
| Registro de Error | ERR | ERR-001 |
| Tipo de Interrupción | TIN | TIN-001 |
| Interrupción | INT | INT-001 |
| Mensaje | MEN | MEN-001 |
| Notificación | NOT | NOT-001 |

Los códigos serán generados automáticamente por la aplicación y no se reutilizarán, incluso cuando el registro asociado sea eliminado o inhabilitado.

---

# Organización de Scripts

La estructura recomendada será:

```
database/

├── 01_roles.sql
├── 02_profesiones.sql
├── 03_especialidades.sql
├── 04_tipos_error.sql
├── 05_tipos_interrupcion.sql
├── 10_seed.sql
└── 20_demo_data.sql
```

Donde:

- **10_seed.sql** ejecutará los scripts de catálogos base.
- **20_demo_data.sql** cargará los datos utilizados para pruebas y demostraciones.

---

# Beneficios

Esta estrategia permite:

- Separar configuración del sistema y datos operativos.
- Facilitar despliegues en diferentes ambientes.
- Mantener una base de datos limpia para producción.
- Ejecutar demostraciones con información consistente.
- Simplificar el mantenimiento de catálogos administrables.
- Evitar dependencias entre datos de negocio y datos de prueba.
