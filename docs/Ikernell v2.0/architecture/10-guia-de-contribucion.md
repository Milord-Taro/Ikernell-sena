# IKernell v2 — Guía de Contribución

> Documento que define el proceso oficial para contribuir al desarrollo de IKernell.

---

# Objetivo

Garantizar que cualquier modificación realizada sobre el proyecto mantenga la calidad, consistencia y arquitectura definidas para IKernell.

Toda contribución deberá respetar los principios establecidos en la documentación de arquitectura.

---

# Flujo de trabajo

Toda contribución seguirá el siguiente proceso.

Análisis

↓

Diseño

↓

Implementación

↓

Validación

↓

Documentación

↓

Commit

---

# Antes de comenzar

Antes de implementar cualquier funcionalidad deberán revisarse los siguientes documentos.

- Visión del Proyecto
- Arquitectura del Dominio
- Design System
- Arquitectura Frontend
- Arquitectura Backend
- Product Backlog

---

# Convenciones

Toda modificación deberá:

- Respetar el Design System.
- Reutilizar componentes existentes.
- Mantener consistencia visual.
- Seguir las convenciones de nombres.
- Actualizar la documentación afectada.

---

# Commits

Se utilizarán Conventional Commits.

Ejemplos.

feat:

fix:

refactor:

docs:

style:

test:

chore:

---

# Pull Requests

Todo Pull Request deberá responder.

¿Qué problema resuelve?

¿Qué cambia?

¿Qué impacto tiene?

¿Qué documentación actualiza?

---

# Definition of Done

Una contribución se considerará finalizada cuando:

✓ Compila correctamente.

✓ Cumple la arquitectura.

✓ Cumple el Design System.

✓ Actualiza la documentación.

✓ No introduce deuda técnica.

✓ Ha sido validada.

---

# Principio Fundamental

La calidad y mantenibilidad del sistema tendrán prioridad sobre la velocidad de implementación.
