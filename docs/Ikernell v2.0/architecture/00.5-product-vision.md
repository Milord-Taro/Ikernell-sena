# IKernell v2 — Product Vision

> Documento que define la visión funcional del producto IKernell y sirve como fundamento para el Product Backlog y la evolución del sistema.

---

# 1. Propósito

IKernell nace como una plataforma web para apoyar la gestión integral de proyectos de desarrollo de software.

Su propósito consiste en facilitar la planificación, ejecución, seguimiento y control de proyectos mediante herramientas que permitan administrar equipos, actividades, incidencias e información relevante durante todo el ciclo de vida del proyecto.

Más allá de registrar información, IKernell busca convertirse en una herramienta de apoyo para la toma de decisiones y el seguimiento operativo de los proyectos.

---

# 2. Problema

Durante el desarrollo de proyectos de software es común que la información se encuentre dispersa entre múltiples herramientas.

Los equipos suelen administrar actividades, errores, interrupciones, documentación y comunicación mediante diferentes plataformas, dificultando el seguimiento del proyecto y reduciendo la trazabilidad de los cambios.

El caso de estudio propone una solución inicial para esta problemática.

IKernell v2 busca ampliar esa propuesta mediante una arquitectura más sólida, una mejor experiencia de usuario y funcionalidades que incrementen el valor del sistema.

---

# 3. Usuarios

El sistema se encuentra orientado principalmente a los siguientes actores.

## Coordinador

Responsable de administrar el sistema.

Funciones principales.

- Administración de usuarios.
- Administración de proyectos.
- Administración de catálogos.
- Seguimiento general.
- Supervisión.

---

## Líder de Proyecto

Responsable de coordinar la ejecución de un proyecto.

Funciones principales.

- Gestión de etapas.
- Gestión de actividades.
- Seguimiento del equipo.
- Registro y análisis de incidencias.

---

## Desarrollador

Responsable de ejecutar las actividades asignadas.

Funciones principales.

- Consultar actividades.
- Registrar avances.
- Registrar errores.
- Registrar interrupciones.
- Actualizar información relacionada con su trabajo.

---

# 4. Objetivos del Producto

IKernell busca proporcionar una plataforma que permita:

- Centralizar la información del proyecto.
- Mejorar la comunicación entre los participantes.
- Facilitar el seguimiento del trabajo.
- Incrementar la trazabilidad.
- Apoyar la toma de decisiones.
- Reducir la pérdida de información.
- Facilitar futuras ampliaciones del sistema.

---

# 5. Alcance Funcional

El sistema cubrirá los siguientes dominios funcionales.

- Gestión de Usuarios.
- Gestión de Roles.
- Gestión de Profesiones y Especialidades.
- Gestión de Proyectos.
- Gestión de Etapas.
- Gestión de Actividades.
- Gestión de Errores.
- Gestión de Interrupciones.
- Gestión de Mensajes.
- Dashboard de seguimiento.
- Configuración del sistema.
- Auditoría.
- Reportes.

---

# 6. Principios del Producto

IKernell deberá caracterizarse por los siguientes principios.

- Simplicidad.
- Consistencia.
- Escalabilidad.
- Modularidad.
- Trazabilidad.
- Usabilidad.

---

# 7. Diferenciadores de IKernell v2

En comparación con la solución mínima propuesta por el caso de estudio, IKernell v2 incorpora una visión orientada a producto.

Entre sus principales diferenciadores se encuentran.

- Arquitectura documentada.
- Design System unificado.
- Componentes reutilizables.
- Auditoría global.
- Timeline de proyectos.
- Mejor trazabilidad.
- Mejor experiencia de usuario.
- Arquitectura preparada para crecimiento.

---

# 8. Visión de Largo Plazo

Aunque el proyecto se desarrolla en el contexto del caso de estudio del SENA, su arquitectura busca aproximarse a la de un producto real.

Las decisiones tomadas durante el overhaul priorizan la mantenibilidad, la reutilización y la posibilidad de incorporar nuevas funcionalidades sin requerir rediseños importantes.
