# Bitácora del Overhaul — IKernell v2

> Registro cronológico de las decisiones, avances, problemas y soluciones implementadas durante el proceso de evolución de IKernell Soluciones Software.

---

# Objetivo

Este documento registra el desarrollo del overhaul desde la planificación hasta la entrega final.

Su propósito es:

- Documentar decisiones de arquitectura.
- Registrar avances del proyecto.
- Justificar cambios realizados.
- Facilitar la sustentación del proyecto.
- Servir como evidencia del proceso de desarrollo durante la etapa práctica.

No reemplaza la documentación técnica ni funcional del proyecto.

Complementa el proceso de desarrollo.

---

# Cómo utilizar esta bitácora

Cada jornada de trabajo deberá registrar únicamente la información relevante.

No registrar cambios menores como:

- Corrección de un color.
- Cambio de un texto.
- Ajustes menores de CSS.

Registrar únicamente cambios que afecten:

- Arquitectura.
- Dominio.
- Base de Datos.
- Backend.
- Frontend.
- UX.
- Documentación.
- Decisiones importantes.

## Decisiones tomadas

### DEC-001

El overhaul mantendrá el alcance funcional del caso de estudio.

Las mejoras estarán enfocadas en calidad, consistencia, reutilización y experiencia de usuario.

---

### DEC-002

Se implementarán únicamente dos funcionalidades de valor agregado.

- Auditoría Global.
- Timeline del Proyecto.

---

### DEC-003

Toda modificación deberá comenzar revisando el dominio antes de modificar la base de datos, el backend o el frontend.

---

### DEC-004

El Product Backlog será el documento rector del desarrollo.

El Master Checklist será utilizado como herramienta diaria de seguimiento.
